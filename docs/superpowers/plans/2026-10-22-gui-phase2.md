# GUI phase 2: connecting the Pode GUI to the engine

Branch `feature/gui-phase2`. Inputs: `docs/handover.md` (Web GUI section), `docs/superpowers/specs/2026-10-21-pode-gui-design.md` ("Data the GUI reads", Phase 2). Rule for every slice: tests first, one commit per slice, no tenant access and no live writes unless the user says so.

## Scope decisions

- The engine is single tenant in v1. Slice 1 writes one tenant (`master`, role Master) from the latest Full check. The replica appears when two-tenant support exists; the GUI lists only tenants in `index.json`.
- The GUI stays free of the PolicyEngine module. A new engine command writes the view models; the GUI reads files only.
- Nothing that writes to a tenant runs from the web server in this phase. Requests are turned into plans and previews (`-WhatIf`); applying stays a deliberate, separate step (the session constraint in the handover, item 4, needs the user's decision).

## Slices

1. **`Export-PEGuiData`** (engine, Public): `-BlueprintName`, `-DataRoot`, `-GuiRoot` (default `<DataRoot>\gui`), `-TenantSlug master`, `-TenantDisplayName`. Reads `Get-PECheck -Latest -Kind Full`, the blueprint (all versions plus `changes\vNNNN.json`) and `Get-PEDecision`. Writes `index.json`, `tenants/<t>/{status,findings,items}.json`, `tenants/<t>/items/<itemId>.json`, `blueprint/versions.json`, `exclusions.json`. Per-type counts are computed here (`Get-PEStatus` only has per-workload totals). Atomic writes, never touches `activity/` or `requests/`. Tests: `tests/GuiExport.Tests.ps1`, including itemId parity with `gui/PEGui.psm1` and a round trip through `Invoke-PEGuiApi`.
2. **`Invoke-PEGuiRequest`** (engine, Public): reads one `requests/<id>.json`, validates it again, maps actions: `Exclude` -> `Set-PEDecision -Kind Unmanaged`, `ExcludeProperty` -> `Noise`, `Unexclude` -> `Remove-PEDecision`, `Accept`/`Promote` -> `New-PERectifyPlan` + `Invoke-PERectify -WhatIf` (config preview into `activity/<jobId>.json`), `RevertBlueprint` -> refused with a clear message until a revert command exists. Writes the job file; re-runs slice 1.
3. **First real Pode run**: install Pode, start `Start-PEGui.ps1` against slice-1 output, check the two untested points in `gui/README.md` (`$WebEvent.Data` parsing, deep-link app shell) with Playwright, fix what breaks.
4. **Docs**: handover and `gui/README.md` updated.

Out of scope until decided: blueprint revert command, live apply from the GUI, replica/two-tenant data, Entra sign-in.
